# 花园视觉系统与当前限制

本文记录当前像素花园的稳定视觉边界，便于维护和作品集说明。产品介绍仍以根目录 `README.md` 为准。

## 视觉定位

花园采用“清晰的中文内容界面 + 游戏化温暖像素庭院”。花园模式把功能入口放回场景：花屋进入卡片模式、
伙伴本体打开规则型对话、长椅旁木箱打开数据与备份；庭院统计和短提示使用与木质外框协调的像素 HUD。
伙伴规则对话使用木框、羊皮纸面板、真实伙伴像素头像和硬边按钮，长文本仍使用清晰中文字体。React 负责
这些可读面板，Phaser 负责地图热点、角色、植物、移动和短暂场景反馈。花园是内容的空间表达，不扩展为
农场经营游戏。

点击花屋后先显示可取消的确认框；确认后经过约两秒的“进入小屋”状态再切换卡片模式。该等待只用于建立
空间过渡，不改变数据，也不掩盖保存操作。从卡片模式返回花园同样显示约两秒的“走出小屋”状态，Canvas
在遮罩后预先创建，避免过渡后再次等待。`prefers-reduced-motion` 下等待文案保留，跳动图标变为静态。

## 像素与地图基准

- 固定世界：`960 × 640`
- 显示舞台：保持 3:2，并按桌面视口高度放大，最大宽度 `1440px`
- 导航网格：`30 × 20`
- 运行时 Tile：`32 × 32`
- Phaser：`pixelArt: true`、`antialias: false`、`roundPixels: true`
- 缩放：`Phaser.Scale.FIT`，Canvas 使用 `image-rendering: pixelated`
- 生命周期：同一页面最多一个 Canvas；离开花园时销毁 Scene、监听器、计时器和 tween

正式地图由 Tiled JSON、最小专用图集和同源的 Collision / Anchors 数据驱动。地图资源失败时使用
Graphics fallback，卡片模式不依赖 Phaser。

## 渐进庭院

基础庭院始终包含花屋、园路、池塘、长椅、入口和花坛。环境成长分为五个全局阶段和六个逻辑区域，
根据当前有槽位的内容植物数量显示连续花带、绿篱和藤蔓。环境植物不可点击，也不代表用户内容。

当前成熟度取自现有植物快照，删除内容后允许视觉阶段下降；“历史最高成熟度只增不减”尚未持久化，
后续若实现需要单独设计数据和备份边界。

## 内容植物

每张卡片通过 Plant 与一个槽位稳定关联。当前有三个内容植物家族：

- 暖阳花
- 蓝紫绒球花
- 粉白星花

已有 `speciesId` 会直接使用；旧数据的空值通过 `plantId` 稳定哈希映射，刷新和备份恢复后不会随机变化。
五个视觉阶段为 `seedling`、`growing`、`budding`、`blooming` 和 `permanent_bloom`。

休眠只降低饱和度和动态，不表示死亡；恢复后回到原成长阶段。内容植物的脚底、阴影、点击区和 y-sort
统一配置，正式资源失败时保留可点击的 Graphics fallback。

## 玩家与伙伴

玩家支持四方向 idle / walk、点击移动和到达植物后自动朝向。猫和狗只改变外观，共用固定位置、
点击事件和 React 伙伴功能，不自由寻路。角色、伙伴和内容植物都按脚底 y 坐标排序。

## 动效与无障碍

现有动效包括植物待机、玩家行走、伙伴待机、新植物种下、休眠、恢复和到达焦点。所有反馈短暂、
可中断，不写入数据库。`prefers-reduced-motion` 下关闭持续摆动，并使用静态高亮表达状态。

来源植物到发芽植物的关系线或粒子连接不在当前范围，列为后续 P2。

## 当前限制与后续

- 只有三个内容植物家族
- 花园成熟度尚未持久化为历史最高值
- 不支持天气、季节、多地图、角色换装或伙伴自由寻路
- 不提供复杂音效和大型粒子系统
- 普通用户语音入口仍为 Post-MVP / Experimental
- 作品集截图保存在项目外，不进入 Git

## 素材与公开使用

当前像素资源来自已记录来源的最小裁切集，仅用于个人、非商业作品集验证。仓库不包含完整参考素材包。
具体裁切和生成方式见 [`GARDEN_ASSET_SOURCES.md`](./GARDEN_ASSET_SOURCES.md)。

若项目公开分发或商业化，必须先替换为原创或具有明确再分发与商业授权的素材，并重新核对所有截图和文档。
